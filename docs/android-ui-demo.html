这次 demo 想让你确认的三件事

待定项选项与取舍
① 底部导航形态 方案 A（5 Tab，与侧栏一一对应）／方案 B（4 Tab + 中央凸起按钮）／方案 C（3 Tab）。
我的建议是 A：零信息丢失、改动最小、最容易做到像素级可控；B 的记账入口更抢眼但要额外处理安全区与弹层遮挡。
② 分类排序 + 删除 已按你的要求做成「编辑模式：左拖动把手 + 右删除」。需要你确认的是两点：
(a) 删除要不要二次确认弹窗？建议 要（分类下有子类与历史账单，误删影响大）；
(b) 拖动是仅编辑模式内可用（现状），还是普通模式也允许？
③ 交互细节 「记一笔」在方案 A 里是 Tab、在方案 B 里是中央按钮，点开后都是同一个弹窗（复用现有 AddBillDialog）。你看哪种更顺手。
关于安全区：手机壳上下那两条虚线标注的是 env(safe-area-inset-top/bottom) 的实际占位 —— 刘海屏与手势条会吃掉这部分高度，桌面端完全没有这个概念，所以底部导航和「记一笔」弹窗的底部按钮都必须算进去，否则会被手势条压住。
关于 hover：桌面端很多反馈靠鼠标悬停（比如分类的删除按钮只在悬停时出现）。触屏没有悬停，这些一律改成常显或点击态 —— 这也是本次 demo 里删除按钮直接画出来的原因。
说明：此页只用于确认视觉方向，数据是假的，未接入任何本地库或云端。
